# 需求說明：汽機車油耗與保養記帳 Agent (Gas & Maintenance Tracker Agent)

## 這是什麼
一個在我自己電腦上執行的 Discord agent。只要它開著，我 Discord Server 裡指定頻道的任何人傳一張汽機車儀表板照片、加油站收據/發票或保養單據進來，它就會自動判斷照片內容、解析里程數與金額、計算油耗與花費，按使用者帳號獨立建檔並回覆上傳者。agent 關掉就不處理。

## 誰會用
我自己的 Discord Server 裡、那個指定頻道的任何人，用手機或電腦都可以傳。

## 使用的流程
1. 有人在頻道裡傳一張汽機車儀表板、加油收據、保養單據照片，或輸入查詢/修正指令。
2. agent 收到，先回一個「處理中」的提示。
3. agent 判斷與解析：
   - 照片類型（儀表板里程、加油收據、保養單據，或非目標照片）。
   - 辨識數值：當前總里程（`odometer` / km）、加油量（`fuel_liters` / L）、消費金額（`cost` / 元）。
4. agent 自動運算與調用歷史資料（評分加分項）：
   - **分人獨立**：依據上傳者的 Discord 帳號（`user_id`）調用該使用者**上一筆里程紀錄**。
   - **數字運算**：計算本次行駛距離（$\Delta\text{km} = \text{當前里程} - \text{上次里程}$）、平均油耗（$\text{km/L}$）與每公里成本（$\text{元/km}$）。
5. agent 把結果記下來（存入 Excel 或 SQLite）、把照片存起來。
6. agent 回覆上傳者本次紀錄結果、油耗與成本計算，並附上該使用者的個人累積養車統計。

## 要記錄的內容（存成一個可以一直往下加的 Excel 檔或 SQLite 資料庫）
- **日期時間** (Timestamp)
- **使用者 ID 與名稱** (`user_id` / `username`) —— **[分人處理]**
- **紀錄類型** (加油 / 保養 / 儀表板 / 非目標照片)
- **當前總里程** (Odometer, km)
- **本次行駛距離** (Trip, km) —— **[運算 / 調用前面結果]**
- **加油量** (Fuel, L)
- **花費金額** (Cost, 元)
- **平均油耗** (km/L) —— **[運算]**
- **每公里成本** (元/km) —— **[運算]**
- **照片存放位置** (Photo Path)

照片另外存進一個資料夾，檔名用「日期時間 + 使用者ID + 類型簡稱」。

## 不是目標照片的時候（非儀表板/加油收據/保養單）
一樣要回覆上傳者「你傳的不是加油收據或儀表板照片，是某某東西」，用 agent 判斷出來的東西說明。這種照片也要建檔與存檔，紀錄類型欄寫「非目標照片」，並註明辨識結果。

## 畫面上 / 回覆上與指令要有（包含評分加分項）
- 收到時先有「處理中」的提示。
- **照片處理完回覆**：辨識數值（里程/加油量/金額）、本次計算結果（行駛距離、平均油耗 km/L、每公里成本）、個人累積統計。
- **額外指令功能（加分項）**：
  - `!stats` / `!養車總計`：調用該使用者的所有歷史紀錄，計算總花費、總里程與歷史總平均油耗。
  - `!chart` / `!趨勢圖`：用 `matplotlib` 自動生成並回傳該使用者的「歷史油耗變化折線圖」圖片。
  - `!fix_last [新里程]`：允許使用者手動修正上一次輸入或辨識錯誤的里程數字。

## 不需要的
- 註冊、登入
- 長時間、大規模的雲端服務（這就是一支開著才會動的本機程式）

## 技術上我知道的
- 用 Python 3.12 + uv（課前已經裝好；實務上也可以用別的語言，這裡先固定）
- 照片用 LLM Vision API（`claude -p` 或 Gemini API）在電腦上記進行圖片解析與 JSON 結構化輸出
- Discord 用 Gateway（bot）模式，不需要 ngrok
- 紀錄存成一個可以持續往下加的 Excel 檔（`openpyxl` / `pandas`）或 SQLite 資料庫
- 設定放在 `.env`：`DISCORD_TOKEN`、`CHANNEL_ID`、`MODEL_NAME`、`DATA_DIR`

## 做事的順序
1. 先把 agent 做好，所有防護與評分加分功能（運算、調用歷史、分人隔離、圖表/修正指令）都開著，自己測到正常。
2. 之後（上課/評分時）再把防護全部關掉做對照。
